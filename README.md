# Flipkart E-commerce Decision Intelligence (capstone)

Synthetic data only: nothing here reflects Flipkart's real records, products, policies or performance. All money is in Indian Rupees (INR); the value column is in hundreds of INR. Every number quoted below is copied from a committed file in `outputs/`, and each file is regenerated by the scripts (Python 3.10+, NumPy only; `common.py` holds the helpers shared by the Parts and never runs a Part on import).

## How to run

From a clean clone of this repository, in this order:

```
pip install -r requirements.txt
python generate_data.py      # must print: 800 10 170 c6f249ba693f1ebeed318d6d5e18de23
python part1.py
python part2.py
python part3.py
python part4.py
```

## Part 1 findings

**R1.1** H0 (mean order value = 8.0, i.e. INR 800) is **rejected**: `z_stat = 2.8930`, which exceeds the critical value 1.96 in absolute size (`mean_value = 8.9382`, `se_value = 0.3243`, 95% interval 8.3026 to 9.5738). A Type I error here would mean concluding that the true average order value differs from INR 800 (and re-planning categories) when it actually equals INR 800. The gap is 0.9382 column units, about INR 94 per order (about 12% of the plan figure). That is statistically clear, but whether it matters depends on volume: across a large order count INR 94 per order adds up, yet the interval is wide (INR 830 to INR 957), so a plan revision should use the interval, not a single point.

**R1.2** `n_required = 1293` orders are needed for a margin of error of 0.5 units (INR 50) at 95% confidence, against 800 rows available. The current sample therefore gives a margin of about 0.64 units (INR 64), not 0.5; the team needs roughly 493 more records to reach the target (`sd_value = 9.1723` is large because order values are right-skewed).

**R1.3** `gd_slope_gap` is 0.0000 (below the 0.001 requirement): the squared-error cost is a smooth bowl with one minimum, and with a sensible step size gradient descent walks to that minimum, which is exactly the point the closed form solves for (cost was already flat at 40.3698 by update 100).

**R1.4** `resid_sd_ratio_raw = 3.7525` versus `resid_sd_ratio_log = 1.0396`. The raw model shows a strong funnel (residual spread in the upper half of fitted values is about 3.8 times that of the lower half); the log-log model removes it (ratio close to 1).

**R1.5** Predictors with |coefficient| above 0.05 (mechanical rule only): ln(X4) (`mr_beta_1 = 1.1576`), X2 complaints (`mr_beta_3 = 0.0940`), X3 discount share (`mr_beta_4 = 0.1067`) and X6 cash-on-delivery (`mr_beta_6 = 0.1518`). `mr_adj_r2 = 0.7403` against `loglog_adj_r2 = 0.6561`, so the extra predictors earn their place: adjusted R² (which penalises extra predictors) still rises by about 0.08.

## Part 2 findings

**R2.1** After 200 updates the losses are, lowest to highest: eta = 1.0 (0.3703), eta = 0.1 (0.3776), eta = 0.01 (0.5091). A rate that is too small barely moves in 200 steps, while on this smooth, standardised problem even the large rate converged fastest (a large rate can overshoot or diverge on other problems; it did not here).

**R2.2** The three largest absolute weights are X3 discount share (0.9013), X1 tenure (-0.5554) and X2 complaints (0.5505). The largest odds ratio is `odds_ratio_X3 = 2.4629`: a customer whose discount-order share is one training SD higher has about 2.5 times the odds of churning, other things fixed.

**R2.3** `blind_accuracy = 0.7875` against 0.8042 accuracy at tau = 0.5: predicting "nobody churns" is almost as accurate as the model, because only 51 of 240 test records churn, so accuracy hides the missed churners. Lowering tau from 0.5 to 0.3 raised recall from 0.4706 to 0.7451 and lowered precision from 0.5455 to 0.4634.

**R2.4** At tau = 0.3 the logistic model has `f1 = 0.5714` and `recall = 0.7451`, against `knn_f1 = 0.3696` and `knn_recall = 0.3333` for KNN (chosen K = 5). Logistic regression is clearly better here.

**R2.5** I would deploy the logistic model at tau = 0.15 (`cost_tau`, chosen by lowest training cost). On the test rows its cost is INR 6050 (`cost_test_at_tau`), against INR 11800 at tau = 0.5 and INR 20400 if nobody is flagged (`cost_test_flag_nobody`). The threshold was chosen on training rows so that the test rows stay untouched and give an honest estimate of the cost on unseen customers.

## Part 3 findings

**R3.1** WCSS drops: WCSS(2) - WCSS(3) = 659.8282, WCSS(3) - WCSS(4) = 108.0739, WCSS(4) - WCSS(5) = 171.0575, WCSS(5) - WCSS(6) = 45.5466. The elbow rule gives `elbow_k = 3`: the biggest saving is from 2 to 3 clusters and the next drop (108.0739) is far below half of it. The drops do not shrink steadily (the 4-to-5 drop is larger than the 3-to-4 drop) because the pinned starting rows give one reproducible solution, not necessarily the global optimum.

**R3.2** Segments (from `part3_segments.csv`):

- **A, "Loyal full-price core"** (322 customers; tenure 47.5 months, discount share 0.2250, loyalty 62.2, outcome rate 0.0186): reward and retain with early access to launches rather than discounts, since they rarely churn and rarely need coupons.
- **B, "High-spend, complaint-prone"** (255; average past order INR 2872, 6.07 complaints, outcome rate 0.2353, highest mean order value 17.1248): fix service friction first (priority support and a complaint-resolution follow-up) to protect the biggest baskets.
- **C, "Bargain-focused newcomers"** (223; tenure 14.4 months, discount share 0.7118, loyalty 38.5): this segment has the **highest outcome rate, 0.4664**. Target it with the retention coupon and with onboarding offers that build loyalty-programme use.

**R3.3** At the cut, single linkage gives 4 clusters: {E2, E3, E6}, {E1}, {E4} and {E5}. Complete linkage gives 2 clusters: {E1, E4, E5} and {E2, E3, E6} (average linkage also gives 2). Single linkage judges a cluster by its closest pair, so it keeps chaining nearby points (E2 joins E3+E6 at 1.4) and its final merges are at similar small heights (2.8, 2.9, 3.4), while complete linkage judges by the farthest pair, so the two groups stay far apart (final merge height 7.9) and a large gap appears right before it.

**R3.4** The mean vector of the standardised data is all zeros. PC1 is driven by X1 tenure (+0.5317) and X5 loyalty (+0.4418) against X3 discount share (-0.5187), X2 complaints (-0.4100) and X4 order value (-0.2916): a "loyal and established versus discount-driven and complaining" axis. Three components keep at least 80% of the variance (cumulative 0.7593 with two, 0.8616 with three). `mean_pc1_segment_A/B/C` are 1.7773, -0.7831 and -1.6709, so PC1 orders the segments in the same sequence as their churn rates (A lowest, C highest).

## Part 4 findings

**R4.1** The best split is S4 (tenure at most 24 months): it has the highest information gain (0.1252) and Gini gain (0.0606), because it separates a high-churn side (86 of 188 customers, 46%) from a low-churn side (33 of 372, 9%). A tree grown until every leaf is pure would memorise noise in the 560 training rows and so overfit; a maximum depth (or a minimum number of rows per leaf) stops it growing too deep.

**R4.2** I would ship the logistic model: at tau = 0.3 it has `f1 = 0.5714` and `recall = 0.7451`, against the stump (0.5532 and 0.7647), soft vote (0.5507 and 0.7451), hard vote (0.5344 and 0.6863) and KNN (0.3696 and 0.3333). Combining models did not help: both votes score a lower F1 than logistic regression alone.

**R4.3** After round 1 normalisation the two misclassified points (3 and 7) carry a total weight of 0.5000 (0.2500 each). Round 2 trusts h2 more because its weighted error (0.1667) is lower than the round-1 error of h1 (0.2500), which gives it the larger weight (`round2_alpha = 0.8047` against `round1_alpha = 0.5493`).

**R4.4** Model A, option 2 (convolutional network):

A 128 x 128 x 3 input needs `fc_layer_params = 50332672` in a dense layer of 1024 neurons but only `conv_layer_params = 1792` in a convolutional layer of 64 filters, because filters are shared across positions.

Model B (recurrent network): W_xh is 128 x 64, W_hh is 128 x 128 and W_hy is 16 x 128, so `rnn_total = 26768`; it does not grow with longer sequences because the same weights are reused at every time step.

For 10 classes I would use ReLU in the hidden layers and a softmax output with categorical cross-entropy loss.

In a very deep plain network the gradient is a product of many small factors on its way back, so the early layers receive almost no learning signal and stop learning. A skip connection adds the layer's input to its output, giving the gradient a direct additive path back to early layers.

## Model-choice memo

To: Head of Retention. Recommendation: ship the logistic-regression model from Part 2, flagging a customer when the churn probability is at least 0.15.

Why: at the 0.3 threshold it scores `f1 = 0.5714` and `recall = 0.7451` on the 240 test customers, against `knn_f1 = 0.3696` for KNN, 0.5532 for the one-question tree and 0.5344 and 0.5507 for the two voting rules. Combining models did not beat it, and it is easy to explain.

Threshold and cost: 0.15 was chosen on training data only, using INR 50 per wasted coupon and INR 400 per lost customer. On the test customers this costs INR 6050, against INR 11800 at 0.5 and INR 20400 if nobody is flagged.

Risk: the test set has only 51 churners and one fixed split, and the data is synthetic, so the INR figures are indicative and should be re-checked on live data before the rollout.

Model A (product pictures) or Model B (review text): neither is worth building before the structured model is in production, as the structured model already answers the churn question with data in hand.

## Limitations

1. The data is synthetic, generated from a script with known structure, so real-world performance and the INR figures are not guaranteed.
2. One fixed 560/240 split is used throughout; the chosen K, the threshold of 0.15 and all test numbers could shift with a different split.
3. The test set has only 51 positive records, so recall, precision and cost carry noticeable sampling noise.
4. The cost figures (INR 50 and INR 400) are rough planning assumptions, and the chosen threshold depends directly on their ratio.
5. K-means uses pinned starting rows, so its solution is reproducible but not necessarily the global optimum; the hierarchical clustering uses a small supplied six-cohort table.
